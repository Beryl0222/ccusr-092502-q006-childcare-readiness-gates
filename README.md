# 托育建设投运证据门

本项目保存 托育建设投运证据门 服务的领域名词、事件信封、就绪口径与事件溯源领域逻辑，便于后续服务在相同语义上演进。

## 解决的问题

获得中央投资的托育综合服务中心有开工、竣工、投运时限，但工程进度、运营团队与班型、消防/食品备案、妇幼机构服务协议分属不同职责方，缺乏共同的就绪口径，容易出现"竣工即投运"的错误放行。本服务以**服务端证据门**统一口径：

- **竣工不等于运营准入**：竣工只是工程里程碑；全日托、半日托、计时托仅在各自所需证据按生效期全部有效时分别开放。
- **按各自生效期关联**：投资批次与三类时限（开工/竣工/投运）、项目里程碑、场地验收、运营方案、人员资质、安全制度、服务包协议、试运行问题统一按生效期/有效期核对。
- **失效只暂停依赖范围**：证照过期、重大整改、合作协议终止只暂停依赖该证据的班型；如食品备案过期仅停全日托，半日托、计时托不受影响。
- **职责分离**：证据由不同职责人签署，提交者不得签署自己提交的材料；已签署结论不原地改写，纠正以同证据链新版本表达。
- **资金可追溯**：放款快照引用当时生效的证据版本；同一回执重送幂等不重复放款；新版本不通过或事后撤销使旧放款进入待追回，追回金额不超过未追回余额。
- **故障恢复**：状态全部由只追加事件重放得到，重启后待复核与待追回事项不丢失。

## 模块

- `contracts/domain.json`：聚合、事件、名词与规则登记。
- `src/envelope.py`：共用事件信封与时间格式校验。
- `src/policy.py`：班型×证据需求矩阵、签署职责矩阵、暂停口径（纯登记，无状态）。
- `src/store.py`：只追加 JSONL 事件存储（写入 fsync，重启自动重放）。
- `src/readiness.py`：证据门领域服务——登记/里程碑/证据提交签署换版撤销/试运行问题/班型开放暂停恢复/放款追回/监管视图。
- `examples/scenario.py`：端到端联调场景。

## 监管视图

`project_view(project_id, at)` 返回：

- 三类时限的余量（天）与是否逾期；
- 每个班型是否开放、是否实际可运营、当前暂停原因与逐项阻断项；
- 待复核队列：待签署、签署不通过、已过期、已撤销、未闭环问题；
- 每笔放款的证据依据快照、已追回/未追回余额与待追回清单及原因。

## 测试与构建

```bash
python3 -m unittest discover -s tests
python3 -m compileall -q src tests
python3 -m examples.scenario
```

以上命令只使用 Python 标准库，可在单个 Linux 应用容器中直接执行。

## 领域边界

事件标识、聚合标识、发生时间和版本用于不同模块之间的确定交接。业务事实一旦被接收就不应原地改写，更正由后续事件（新版本、撤销、追回）表达。持久化目前为本地 JSONL，权限认证与对外 HTTP 接口由正式服务实现。
